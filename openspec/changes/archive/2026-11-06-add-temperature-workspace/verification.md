# Проверка реализации

Проверено 6 ноября 2026 года. Реальные вызовы модели не выполнялись.

## Автоматические проверки

- `backend/`: `python -m pytest -q` — 180 тестов успешно. Использован Python из проектного `.venv`; HTTPX MockTransport подменяет провайдера.
- `frontend/`: `npm test` — 178 тестов успешно, 7 файлов; HTTP-ответы и Web Locks подменяются в тестовом окружении.
- `frontend/`: `npm run lint` и `npm run build` — успешно.
- В окружении backend остаётся предупреждение Starlette об устаревшей связке TestClient/httpx; ошибок тестов нет. Зависимости ради этого изменения не обновлялись.

## Chromium: ручной интеграционный сценарий

Использован отдельный тестовый origin `http://localhost:5174`, две вкладки приложения и локальная подмена `window.fetch` для `/api/ask`. Запросы перехватывались до сети; проверены как немедленные, так и отложенные ответы.

- Первый экран содержит прежние две вкладки effort и пять подходов, форма и переписка не дублируются.
- Левое меню отображается модально; Tab и Shift+Tab циклически остаются внутри. Попытка сфокусировать фон не переводит фокус за панель. Escape закрывает меню, возвращает фокус бургеру и обновляет aria-expanded.
- Выбор «Температура» закрывает панель; доступны только три температурные вкладки, по умолчанию 0.7, рассуждения обозначены отключёнными.
- Ctrl+Enter отправляет один direct с числовой temperature без effort. Карточка сохраняет вопрос, дату, «Ответ», длительность и токены; метаданные показывают температуру вместо effort.
- Черновик температуры и черновик исходного раздела сохраняются независимо при переключении, температурная переписка остаётся в своём диалоге.
- В первой вкладке запущен отложенный температурный вопрос, во второй — исходный direct/low. Оба ожидания активны без ошибок, UUID поколения общий, контекст исходного раздела пуст, а температурный содержит только свою предыдущую успешную пару.
- Очистка из температурного раздела удаляет переписку обеих вкладок и их черновики, отменяет оба активных ожидания, меняет UUID. В localStorage остаётся только новый UUID без текста.
- После очистки новый вопрос исходного раздела получает пустой контекст и новый UUID. Позднее завершение старых подменённых запросов не восстанавливает удалённую историю и не удаляет новый ответ.
- Консоль ошибок обеих вкладок пуста.

Поддержка выбранных параметров самим OpenCode Go не подтверждалась реальной генерацией; автоматические проверки подтверждают отправляемый контракт и безопасную обработку отказов.

## Ревью переиспользования

- `use-conversation-controller.ts` — единственный жизненный цикл отправки, отмены, очистки черновиков и применения результата для всех областей.
- Оба раздела используют существующий store и общие Tabs, QuestionForm и AnswerPanel; различаются только настройки, ключ области и метаданные.
- Температурная генерация использует прежние solver/direct и complete, включая языковую инструкцию, статистику и обработку ошибок.
- Новых зависимостей нет. Убрана вложенная тернарная проверка метаданных; устаревший конструктор v1-данных перенесён из production-кода в тестовые fixtures. После ревью тесты, lint и сборка повторно прошли; `git diff --check` не обнаружил ошибок.
- Тестовая переписка очищена, браузерные подмены fetch удалены перезагрузкой; оставшаяся вкладка показывает обычный исходный раздел приложения.
