# Spec Delta

## ADDED Requirements

### Requirement: Температурная ветка прямого ответа
`POST /api/ask` SHALL принимать необязательное поле `temperature`. Его наличие SHALL выбирать температурную ветку только для `mode: direct`, без поля effort. Допустимы только числовые `0`, `0.7`, `1.2`; строки, boolean, null и остальные значения SHALL отклоняться с HTTP 422 до вызова модели. Отсутствующий mode SHALL означать `direct`; действуют прежние правила вопроса, UUID и истории.

#### Scenario: Три разрешённые температуры
- **WHEN** клиент отправляет непустой вопрос, допустимый UUID, `history.direct` и одно из значений `temperature: 0`, `0.7`, `1.2`, не передавая effort
- **THEN** сервер принимает запрос и выполняет один прямой ответ с выбранной температурой
- **AND** значение `0` не заменяется значением по умолчанию

#### Scenario: Отсутствие mode
- **WHEN** клиент отправляет `{"question": "Привет", "temperature": 0.7}`
- **THEN** сервер обрабатывает температурный `direct` без истории и с новым UUID

#### Scenario: Несовместимые настройки
- **WHEN** температурный запрос содержит effort, включая null, либо mode `steps`, `prompt`, `roles` или `compare`
- **THEN** сервер возвращает HTTP 422 с безопасным строковым detail и не обращается к провайдеру

#### Scenario: Невалидная температура
- **WHEN** temperature равна `"0.7"`, `false`, null, `-1`, `0.5`, `2` или не является конечным числом
- **THEN** сервер возвращает HTTP 422 без обращения к провайдеру

#### Scenario: Системные настройки остаются серверными
- **WHEN** клиент передаёт поле `thinking` или иной неизвестный параметр генерации
- **THEN** сервер отклоняет лишнее поле, не позволяя изменить серверную политику рассуждений

## MODIFIED Requirements

### Requirement: Вопрос и параметры запроса
Без поля temperature `POST /api/ask` SHALL принимать непустой строковый `question` с удалением крайних пробелов, `mode` из `direct`, `steps`, `prompt`, `roles`, `compare`, `effort` из `low`, `max` и UUID `conversation_id`. По умолчанию SHALL использоваться `direct`, `low`, пустая история и новый UUID на запрос; верхнего ограничения длины вопроса приложение SHALL не задавать. При наличии temperature SHALL действовать температурная ветка прямого ответа.

#### Scenario: Запрос только с вопросом
- **WHEN** клиент отправляет `{"question": "  Привет  "}`
- **THEN** сервер обрабатывает вопрос `Привет` в режиме `direct` с effort `low`, без истории и с новым UUID

#### Scenario: Недопустимые входные данные
- **WHEN** вопрос отсутствует, пуст после обрезки, имеет неверный тип, либо переданы неизвестный mode, effort, невалидный UUID или лишние поля
- **THEN** сервер возвращает HTTP 422 с безопасным строковым `detail` без обращения к провайдеру

#### Scenario: Длинный вопрос
- **WHEN** клиент отправляет допустимый вопрос длиной 20000 символов
- **THEN** сервер передаёт весь вопрос модели без обрезки приложением

### Requirement: Структурированный ответ API
Успешный ответ SHALL содержать только `question`, `date`, `mode`, `effort`, `tokens`, `results`; температурная ветка SHALL дополнительно содержать `temperature`, иметь `effort: null` и `mode: direct`. Результат SHALL содержать `mode`, `answer`, `tokens`, `duration_ms`, `stages`, `error`; этап — `name`, `content`, `tokens`. Сервер SHALL формировать date в UTC, отражать вопрос и настройки; счётчики SHALL быть неотрицательными целыми либо допустимым null при ошибке.

#### Scenario: Ответ одиночного подхода
- **WHEN** допустимый запрос `direct` без temperature успешно обработан
- **THEN** HTTP 200 содержит один результат `direct` с непустым ответом, `error: null`, пустыми `stages`, токенами и длительностью
- **AND** `date` является временем формирования ответа сервером с часовым поясом UTC
- **AND** effort равен выбранному `low` или `max`, поле temperature отсутствует, набор прежних шести полей не меняется

#### Scenario: Опубликованная схема
- **WHEN** клиент запрашивает `/openapi.json`
- **THEN** схема API описывает обязательные поля ответа, формат `date-time` и запрет дополнительных полей в моделях запроса и ответа
- **AND** различает прежний ответ и температурный ответ с обязательной temperature и `effort: null`

#### Scenario: Температурный ответ
- **WHEN** запрос `temperature: 0` успешно обработан
- **THEN** HTTP 200 содержит исходную оболочку ответа с дополнительным `temperature: 0` и `effort: null`
- **AND** results содержит единственный результат `direct` с прежним набором полей, пустыми stages и реальными токенами
