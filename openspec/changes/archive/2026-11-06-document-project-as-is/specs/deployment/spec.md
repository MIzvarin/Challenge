# Spec Delta

## Purpose

Возможность фиксирует существующие способы локального запуска и приватного размещения проекта. Она описывает конфигурацию, границы публичных файлов, сборку контейнера и передачу исходников без секретов.

## ADDED Requirements

### Requirement: Серверная конфигурация
Приложение SHALL читать `OPENCODE_GO_API_KEY` и `OPENCODE_GO_MODEL` из корневого `.env` с приоритетом переменных окружения процесса. Пустая настройка модели SHALL использовать `deepseek-v4.1-flash`, иная модель SHALL отклоняться при загрузке конфигурации; старые переменные другого провайдера SHALL не использоваться.

#### Scenario: Приоритет окружения
- **WHEN** файл и окружение содержат разные значения API-ключа
- **THEN** сервер использует ключ из окружения, не раскрывая его в строковом представлении настроек

#### Scenario: Неподдерживаемая модель
- **WHEN** `OPENCODE_GO_MODEL` содержит идентификатор вне разрешённого списка
- **THEN** конфигурация отклоняется вместо запуска с произвольной моделью

### Requirement: Локальный интерфейс через прокси
Режим разработки SHALL предоставлять интерфейс на `127.0.0.1:5173` и проксировать `/api` на `http://127.0.0.1:8000`. Браузер SHALL не обращаться напрямую к API модели; просмотр статики через preview SHALL не считаться полноценным запуском API.

#### Scenario: Отправка вопроса при локальной разработке
- **WHEN** фронтенд и бэкенд запущены по инструкции README
- **THEN** браузер отправляет запрос на `/api/ask` своего origin, а dev-сервер передаёт его бэкенду

### Requirement: Раздача только собранного интерфейса
При наличии `frontend/dist` бэкенд SHALL раздавать его по корневому URL, сохраняя API. Корень репозитория, `.env` и серверные исходники SHALL не становиться публичной статикой; при отсутствии сборки API SHALL оставаться доступным.

#### Scenario: Запуск после сборки
- **WHEN** собранный интерфейс находится в `frontend/dist` и бэкенд перезапущен
- **THEN** `/` открывает интерфейс, а `/api/health` возвращает состояние приложения
- **AND** запросы `/.env` и `/backend/app/config.py` не возвращают содержимое этих файлов

### Requirement: Контейнер без встроенных секретов
Сборка контейнера SHALL собирать фронтенд отдельно и запускать Python-бэкенд с готовой статикой от непривилегированного пользователя, одним worker и без доверия proxy-заголовкам. `.env` SHALL исключаться из контекста сборки; ключ SHALL передаваться при запуске через окружение, а проверка здоровья SHALL использовать `/api/health` без генерации.

#### Scenario: Сборка и запуск по существующей инструкции
- **WHEN** контейнер собирают из Dockerfile и запускают с `--env-file`
- **THEN** в работающем контейнере доступны API и собранный интерфейс, процесс приложения не работает от root и ключ не требуется на этапе сборки
- **AND** проверка здоровья не расходует квоту провайдера

### Requirement: Приватная схема доступа
Инструкция размещения SHALL привязывать опубликованный порт контейнера только к `127.0.0.1` сервера и предоставлять доступ владельцу через SSH-туннель на localhost. Она SHALL предупреждать, что приложение не имеет встроенной авторизации и для публичного размещения нужны отдельные авторизация, HTTPS и защита квоты.

#### Scenario: Доступ к VPS без домена
- **WHEN** владелец запускает контейнер с `127.0.0.1:8000:8000` и SSH-туннель локального порта 18000 на серверный 8000
- **THEN** интерфейс доступен в его браузере по `http://localhost:18000`, без публикации порта 8000 на внешних адресах VPS
- **AND** инструкция не объявляет loopback защитой от других локальных процессов сервера

### Requirement: Ограниченный архив развёртывания
Скрипт упаковки SHALL формировать `challenge-deploy.tar.gz` из явного списка исходников и файлов сборки, включая пример настроек, но не локальный `.env`, историю Git, установленные зависимости или Python-кэш.

#### Scenario: Подготовка исходников к переносу
- **WHEN** владелец запускает `bash scripts/package-deploy.sh`
- **THEN** архив содержит необходимые исходники и `.env.example`, но не секреты из `.env`, `.git`, `node_modules` и локальное виртуальное окружение
