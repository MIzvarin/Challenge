# Proposal

## Why

Нужно заменить набор моделей существующего раздела на Kimi K2.7 Code, Grok 4.7 и GPT‑6 Luna, сохранив выбор вкладкой по аналогии с «Температурой». Остальное взаимодействие чата остаётся прежним; пользователь разрешил полный сброс накопленной истории при обновлении.

## What Changes

- В существующем разделе «Модели» заменить вкладки на Kimi K2.7 Code → Grok 4.7 → GPT‑6 Luna; по умолчанию выбирать Kimi. Beam Free и Gemini 4 Argon больше не доступны для новых вопросов.
- Каждый вопрос отправлять только выбранной модели: один вопрос — один прямой ответ, без автоматического запуска остальных моделей. Переключение вкладок само по себе не вызывает API.
- Сохранять отдельные историю, контекст и черновик каждой модели; показывать прежние вопрос, дату, карточку «Ответ», длительность, токены и ошибки.
- Использовать существующий серверный ключ Go: Kimi через Chat Completions, Grok и GPT через Responses API вместо прежнего Google Generate Content.
- **BREAKING**: однократно сбросить всю локальную историю всех разделов, включая Kimi, старые копии и UUID поколения, при первом запуске обновлённой версии. Пользователь явно разрешил удаление; перенос и архив старых диалогов не требуются. Последующие перезагрузки сохраняют новые сообщения.
- Сохранить общую очистку, межвкладочную синхронизацию и защиту от поздних ответов. Не менять контракты температурных и reasoning-запросов, подходы и исходный экран; единственное исключение — согласованный сброс их истории и смена сессий при обновлении.
- Вне объёма: новые провайдеры, ключи, авторизация, серверная история, произвольные модели и биллинг. Автоматического сравнения моделей по-прежнему нет.

## Capabilities

### New Capabilities
- `model-comparison`: прямой ответ выбранной из трёх фиксированных моделей, отдельный API и изолированный контекст каждой вкладки. Путь capability сохраняется; автоматическое сравнение не входит в объём.

### Modified Capabilities
- `web-interface`: третий раздел меню и три вкладки моделей по аналогии с температурами.
- `model-integration`: маршрутизация Go по новому набору моделей, проверка Responses API без изменения DeepSeek-пути.
- `conversation-history`: три диалога нового набора, однократный полный сброс при обновлении, затем прежнее сохранение и общая очистка.

## Impact

Backend: реестр, схемы, solver, новый Responses-адаптер и удаление более не используемого Google-адаптера. `/api/ask-models` сохраняет структуру, меняется allowlist model; `/api/ask` неизменен. Frontend: порядок вкладок, scopes, валидатор, однократный reset до загрузки истории. Проверки: MockTransport, pytest, Vitest/Testing Library без реальной генерации. README и docs/deploy.md должны предупредить об удалении истории и необходимости обновить все вкладки. Новых секретов и обязательных зависимостей нет.
