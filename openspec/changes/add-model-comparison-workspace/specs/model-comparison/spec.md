# Spec Delta

## Purpose

Прямые ответы выбранной модели в отдельном разделе с тремя вкладками, независимыми диалогами, достоверными метаданными и безопасной обработкой ошибок.

## ADDED Requirements

### Requirement: Прямой ответ выбранной модели
Каждый принятый вопрос раздела «Модели» SHALL запускать ровно один прямой ответ выбранной во вкладке модели: Kimi K2.7 Code, Grok 4.7 или GPT‑6 Luna. Система SHALL не вызывать остальные модели для этого вопроса, не добавлять подходы, автоматические повторы или подмену модели.

#### Scenario: Вопрос выбранной модели
- **WHEN** пользователь выбирает Kimi K2.7 Code и отправляет непустой вопрос
- **THEN** выполняется только один вызов Kimi и возвращается только её ответ
- **AND** Grok и GPT не вызываются

### Requirement: Отдельный контракт выбранной модели
`POST /api/ask-models` SHALL принимать question, обязательный model из kimi-k2.7-code, grok-4.7, gpt-6-luna, необязательные conversation_id и history с единственным допустимым ключом direct. SHALL действовать прежние правила вопроса, UUID и пар user/assistant. При отсутствии history SHALL использоваться пустая история, при отсутствии UUID — новый. Effort, temperature, неизвестные модели и лишние поля SHALL отклоняться до генерации.

#### Scenario: Неверные параметры
- **WHEN** model отсутствует или неизвестен, переданы temperature, effort, system-сообщение, ключ истории кроме direct, невалидный UUID либо неполная пара сообщений
- **THEN** сервер возвращает 422 со строковым безопасным detail без вызова Go

#### Scenario: Минимальный запрос
- **WHEN** отправлено `{"question":"  Привет  ","model":"kimi-k2.7-code"}`
- **THEN** сервер отправляет вопрос «Привет» только Kimi с пустой историей и новым UUID

#### Scenario: Исключённые модели
- **WHEN** запрос содержит model beam-free или gemini-4-argon
- **THEN** сервер возвращает 422 без обращения к Go и без автоматической замены модели

### Requirement: Ответ и ошибка одиночной модели
Успешный ответ SHALL содержать только question, date в UTC, model, mode direct, effort null, tokens и results с одним результатом direct прежней структуры: mode, answer, tokens, duration_ms, stages, error. Stages SHALL быть пустым, error — null; tokens SHALL отражать фактический расход единственного вызова. Ошибка SHALL возвращаться соответствующим HTTP-статусом со строковым безопасным detail, а не результатом внутри HTTP 200.

#### Scenario: Успешный ответ
- **WHEN** выбранная модель завершила ответ с расходом 0 токенов
- **THEN** HTTP 200 содержит её model, единственный результат direct с непустым ответом и tokens 0 без метаданных температуры

#### Scenario: Выбранная модель недоступна
- **WHEN** Go возвращает 403 для выбранной Grok
- **THEN** клиент получает HTTP 503 с безопасным detail без частичного ответа
- **AND** другие модели не вызываются, предыдущая переписка не удаляется

### Requirement: Изолированный контекст модели
Выбранная модель SHALL получать все успешные пары только своего диалога без автоматического сокращения. Ошибки и ответы других моделей или разделов SHALL не входить в её контекст.

#### Scenario: Возврат во вкладку модели
- **WHEN** пользователь получил ответ Kimi, пообщался с Grok и вернулся с уточнением к Kimi
- **THEN** history.direct содержит все успешные пары только Kimi, без ответов Grok и ошибочных попыток

### Requirement: Общие ограничения приложения
Новый endpoint SHALL использовать существующий серверный ключ, общий лимит 10 вопросов за 60 секунд на процесс, no-store и прежние безопасные HTTP-ошибки одиночного запроса. Один вопрос SHALL занимать одну позицию лимита. Схемы SHALL запрещать лишние поля и публиковаться в OpenAPI; `/api/ask` и `/api/health` SHALL сохранять прежний контракт.

#### Scenario: Общий лимит и отсутствующий ключ
- **WHEN** запрос поступает без ключа либо после десяти принятых вопросов любого раздела за минуту
- **THEN** возвращается соответственно 503 либо 429 с Retry-After без генерации
- **AND** ответ содержит Cache-Control no-store
