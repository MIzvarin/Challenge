# Spec Delta

## MODIFIED Requirements

### Requirement: Структурированный ответ API
Успешный ответ SHALL содержать только `question`, `date`, `mode`, `effort`, `tokens`, `cost`, `results`; температурный ответ SHALL дополнительно содержать `temperature`, иметь `effort: null` и `mode: direct`. Результат SHALL содержать `mode`, `answer`, `tokens`, `cost`, `duration_ms`, `stages`, `error`; этап — `name`, `content`, `tokens`, `cost`. Сервер SHALL формировать date в UTC, отражать вопрос и настройки; счётчики SHALL быть неотрицательными целыми либо допустимым null при ошибке.

#### Scenario: Ответ одиночного подхода
- **WHEN** допустимый запрос `direct` без temperature успешно обработан
- **THEN** HTTP 200 содержит один результат `direct` с непустым ответом, `error: null`, пустыми `stages`, токенами и длительностью
- **AND** `date` является временем формирования ответа сервером с часовым поясом UTC
- **AND** effort равен выбранному `low` или `max`, поле temperature отсутствует, к прежним шести полям добавлено обязательное поле cost

#### Scenario: Опубликованная схема
- **WHEN** клиент запрашивает `/openapi.json`
- **THEN** схема API описывает обязательные поля ответа, формат `date-time` и запрет дополнительных полей в моделях запроса и ответа
- **AND** различает прежний ответ и температурный ответ с обязательной temperature и `effort: null`
- **AND** описывает обязательный nullable cost в ответах, результатах и этапах

#### Scenario: Температурный ответ
- **WHEN** запрос `temperature: 0` успешно обработан
- **THEN** HTTP 200 содержит исходную оболочку ответа с дополнительным `temperature: 0` и `effort: null`
- **AND** results содержит единственный результат `direct` с пустыми stages, реальными токенами и обязательным nullable cost

## ADDED Requirements

### Requirement: Контракт денежной оценки
Оба API генерации SHALL возвращать cost на уровнях ответа, результата и этапа как null либо объект только с `amount`, `currency`, `pricing_version`, `source`. amount SHALL быть строкой неотрицательного десятичного числа без экспоненты, currency — `USD`, pricing_version — непустой версией, source — HTTPS URL опубликованного тарифа. Запросы SHALL не принимать цены от клиента.

#### Scenario: Модельный ответ
- **WHEN** `/api/ask-models` возвращает оценённый прямой ответ Kimi, Grok или GPT
- **THEN** model и прежние поля сохраняются, cost ответа равен cost единственного результата
- **AND** amount передаётся строкой, например `"0.001446"`, не JSON float

#### Scenario: Цена недоступна
- **WHEN** завершённый ответ имеет только достоверный общий расход
- **THEN** сервер возвращает HTTP 200 с `cost: null`, не строкой «неизвестно» и не объектом с amount ноль
- **AND** отсутствие детализации цены не меняет прежние правила ошибок некорректного total_tokens

#### Scenario: Клиент задаёт цену
- **WHEN** клиент добавляет cost или тариф к запросу любого API генерации
- **THEN** сервер отклоняет лишнее поле с HTTP 422 до вызова провайдера
