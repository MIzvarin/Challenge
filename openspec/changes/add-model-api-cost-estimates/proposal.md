# Proposal

## Why

Сейчас карточки показывают длительность и общее количество токенов, но не позволяют сравнить денежную стоимость разных моделей и многоэтапных подходов. Пользователю нужна приблизительная стоимость ответа по опубликованным API-тарифам во всех разделах, а не фактическое списание подписки OpenCode Go.

## What Changes

- Добавить «Примерная стоимость: ≈ … USD» в карточки всех разделов: подходы с обоими effort, сравнение, температуры и модели Kimi/Grok/GPT.
- Считать стоимость на сервере по детализации usage каждого вызова и опубликованным тарифам для точного model ID; учитывать вход, выход, кэш, тарифы длинного контекста и пиковые часы, когда они применимы.
- Суммировать стоимость всех вызовов подхода, включая генерацию промпта и промежуточные роли, без повторного прибавления стоимости этапов. В сравнении дополнительно показывать общий итог только при известной стоимости всех четырёх результатов.
- При неизвестной стоимости показывать «Стоимость недоступна», а не ноль; отсутствие детализации для цены не превращает корректный ответ с достоверным total_tokens в ошибку.
- Сохранять полученную оценку вместе с ответом. Старую историю принимать без цены, не удалять и не пересчитывать по новым тарифам.
- **BREAKING** для клиентов со строгим набором полей: расширить ответы `/api/ask` и `/api/ask-models` обязательным nullable `cost` на уровнях ответа, результата и этапа. Форматы запросов не меняются; backend и frontend обновляются согласованно.
- Вне объёма: реальные списания/остатки Go, деление абонплаты на запросы, прямые вызовы API других провайдеров, новые модели, прогноз до генерации, валютная конвертация, общий бюджет аккаунта и автоматическое обновление тарифов по сети.

## Capabilities

### New Capabilities
- `response-cost`: правила оценки денежной стоимости по usage и версионированным публичным тарифам, агрегация и неизвестные значения.

### Modified Capabilities
- `question-api`: nullable денежные метаданные в обеих разновидностях API генерации, результатах и этапах.
- `web-interface`: цена в карточках всех разделов, итог сравнения и однозначная маркировка оценки.
- `conversation-history`: сохранение оценок без пересчёта и чтение прежней истории без новых полей.

## Impact

Backend: `opencode_go.py`, `responses_go.py`, `solver.py`, `schemas.py`, отдельные модули нормализации usage и тарифов. Frontend: `api.ts`, `AnswerPanel.tsx`, чтение истории через `conversations.ts` и существующий store. Проверки: pytest с HTTPX MockTransport, Vitest/Testing Library, API/OpenAPI, localStorage и межвкладочные регрессии; без реальной генерации. README и инструкция обновления должны описать смысл оценки, источник/дату тарифов, неизвестные цены и согласованный релиз. Новых секретов, серверного хранения диалогов и обязательных внешних зависимостей не требуется.
