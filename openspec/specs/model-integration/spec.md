# model-integration Specification

## Purpose

Возможность описывает существующий обмен сервера с DeepSeek через OpenCode Go. Она закрепляет параметры генерации, идентичность сессий, проверку результатов и безопасную обработку отказов внешнего сервиса.

## Requirements

### Requirement: Серверный вызов OpenCode Go
Сервер SHALL вызывать `https://opencode.ai/inference/go/openai/v1/chat/completions` с моделью `deepseek-v4.1-flash`, серверным ключом в `Authorization: Bearer`, идентификатором клиента в `User-Agent` и идентификатором сессии в `x-opencode-session`. Браузер SHALL обращаться только к локальному API приложения без ключа провайдера.

#### Scenario: Успешная отправка вопроса
- **WHEN** сервер обрабатывает допустимый запрос с настроенным ключом
- **THEN** обращение к Go содержит выбранную разрешённую модель, сообщения и серверные заголовки
- **AND** API-ключ не включается в ответ приложения браузеру

### Requirement: Выбранная интенсивность на всех этапах
Каждое обращение SHALL содержать `thinking: {"type": "enabled"}`, выбранный `reasoning_effort` (`low` или `max`) и `stream: false`. Настройка SHALL одинаково применяться к генератору промпта, всем ролям и всем подходам сравнения.

#### Scenario: Сравнение с максимумом рассуждений
- **WHEN** запрос `compare` с effort `max` полностью успешен
- **THEN** все семь обращений содержат включённые рассуждения и `reasoning_effort: max`

### Requirement: Отсутствие бюджетов генерации приложения
Система SHALL не отправлять `max_tokens`, `max_completion_tokens`, `stop`, `budget_tokens` или `response_format` и не включать ограничения длины ответа в инструкции подходов. Собственные ограничения провайдера не отменяются этим контрактом.

#### Scenario: Длинное решение
- **WHEN** приложение отправляет задачу любым подходом
- **THEN** запрос не содержит бюджета токенов, стоп-последовательностей или требования JSON-формата ответа модели

### Requirement: Стабильные изолированные сессии
Сервер SHALL получать устойчивый `x-opencode-session` из `conversation_id`, effort, режима и конкретного подхода. Он SHALL совпадать для всех этапов и последующих вопросов одной комбинации, отличаться между комбинациями и изменяться при новом `conversation_id`; контекст SHALL всегда передаваться явно в сообщениях.

#### Scenario: Продолжение одного диалога
- **WHEN** два вопроса `roles` имеют одинаковые `conversation_id` и effort
- **THEN** все три этапа обоих вопросов используют один session ID

#### Scenario: Разные области контекста
- **WHEN** с тем же `conversation_id` выполняются одиночный `direct`, `direct` внутри сравнения и `direct` другого effort
- **THEN** эти три области используют разные session ID

#### Scenario: Очистка и совместимость старого клиента
- **WHEN** клиент меняет UUID после очистки либо не передаёт `conversation_id` в двух независимых запросах
- **THEN** новые запросы используют отличающиеся от предыдущих session ID

### Requirement: Проверка завершённого ответа и расхода
Система SHALL принимать генерацию только при HTTP 200 без ошибок, наличии первого варианта с `finish_reason: stop`, непустого строкового `message.content` и целого неотрицательного `usage.total_tokens`. Итоговый текст SHALL обрезаться по краям; внутренний `reasoning_content` SHALL не подменять ответ и не попадать в результат приложения.

#### Scenario: Допустимый нулевой расход
- **WHEN** провайдер вернул завершённый ответ `  Ответ  ` и `total_tokens: 0`
- **THEN** приложение принимает текст `Ответ` и расход 0 без подстановки выдуманных значений

#### Scenario: Нет достоверного ответа или статистики
- **WHEN** провайдер вернул пустой текст, только внутренние рассуждения, неверный JSON, пустой список вариантов либо отсутствующую или некорректную статистику
- **THEN** генерация считается ошибкой 502, а не успешным ответом

### Requirement: Отказ от частичной генерации при ошибке
Система SHALL отклонять текст при `finish_reason`, отличном от `stop`, и ошибки в поле `error` верхнего уровня или первого варианта даже внутри HTTP 200. Для `length` SHALL сообщаться об ограничении провайдера, а частичный текст SHALL не выдаваться за итог.

#### Scenario: Ответ оборван ограничением провайдера
- **WHEN** провайдер возвращает `finish_reason: length` с непустым или отсутствующим текстом
- **THEN** генерация завершается ошибкой 502 с объяснением ограничения провайдера

#### Scenario: Ошибка внутри HTTP 200
- **WHEN** HTTP 200 содержит `error` с кодом 429 и частичный текст
- **THEN** приложение обрабатывает отказ как лимит провайдера и не публикует частичный текст

### Requirement: Безопасное преобразование ошибок провайдера
Система SHALL преобразовывать отказы Go: 401/402/403 в 503, 429 в 429, 408/504/524 в 504, прочие ошибки в 502. Ответ 400 с сообщением о необходимости Global SHALL становиться 503 с инструкцией настройки региона. Клиент SHALL получать подготовленные сообщения без сырой диагностики; `Retry-After` при 429 SHALL передаваться только для строки из ASCII-цифр.

#### Scenario: Отказ доступа к DeepSeek
- **WHEN** Go возвращает 403 либо 400 с `This Go model requires Global regions.`
- **THEN** клиент получает безопасное сообщение о доступе или регионе Global со статусом 503 в одиночном режиме
- **AND** ключ, исходная диагностика и метаданные провайдера не раскрываются

#### Scenario: Лимит провайдера
- **WHEN** Go возвращает 429 с `Retry-After: 15`
- **THEN** одиночный запрос получает HTTP 429, безопасное сообщение о лимитах Go и `Retry-After: 15`

### Requirement: Ограниченное сетевое ожидание без подмены модели
Обращение к провайдеру SHALL иметь тайм-аут подключения 10 секунд и сетевого бездействия 180 секунд. Тайм-аут SHALL становиться ошибкой 504, ошибка соединения — 502; при отказе система SHALL не повторять генерацию автоматически и не переключать модель или endpoint.

#### Scenario: Модель недоступна
- **WHEN** Go возвращает 404
- **THEN** выполняется только исходное обращение и возвращается ошибка с рекомендацией проверить настройку модели, без резервного провайдера

#### Scenario: Превышено время ожидания
- **WHEN** обращение завершается сетевым тайм-аутом
- **THEN** генерация получает безопасную ошибку 504 без автоматического повторения
