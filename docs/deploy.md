# Приватное размещение на VPS без домена

Docker собирает React и запускает FastAPI вместе с ним. Node.js нужен только на
этапе сборки. Python 3.15.2 уже включён в образ. Приложение работает от непривилегированного
пользователя, с одним worker и автозапуском контейнера после перезагрузки сервера.

## 1. Перенос с Mac

В корне проекта:

```sh
bash scripts/package-deploy.sh
scp challenge-deploy.tar.gz root@IP_СЕРВЕРА:/root/
```

Подставьте свой IP. Если SSH использует нестандартный порт, добавьте в `scp`
параметр `-P ПОРТ`. Архив содержит только исходники и пустой пример настроек;
локальный `.env`, зависимости и история Git в него не входят.

## 2. Сборка на VPS

На сервере с установленным Docker:

```sh
install -d -m 700 /opt/challenge
tar -xzf /root/challenge-deploy.tar.gz -C /opt/challenge
cd /opt/challenge
docker build -t challenge:local .
```

## 3. Секреты

Если `.env` ещё нет, создайте его из `.env.example` и заполните API-ключ редактором
на VPS. Не вставляйте ключ в команду оболочки, Dockerfile, Git или переписку.

```sh
cp -n .env.example .env
chmod 600 .env
nano .env
```

Нужные переменные:

```dotenv
OPENCODE_GO_API_KEY=ваш_ключ_OpenCode_Console
OPENCODE_GO_MODEL=deepseek-v4.1-flash
```

Ключ должен принадлежать workspace с активной подпиской Go. Для DeepSeek в
OpenCode Console разрешите **Settings → Privacy → Regions → Global**. Проверьте
условия использования Go: тариф предназначен для coding-агентов, а не произвольного
публичного чат-сервиса. Отключите **Extra Usage**, если не хотите списаний с баланса
сверх подписки; приложение не меняет эту настройку аккаунта.

`.env` исключён из контекста Docker и не попадает в образ. Docker передаёт его
значения в окружение при запуске контейнера. Не публикуйте вывод `docker inspect`:
администраторы Docker могут прочитать переменные окружения контейнера.

## 4. Запуск

Из `/opt/challenge`:

```sh
docker run -d \
  --name challenge \
  --restart unless-stopped \
  --env-file /opt/challenge/.env \
  --read-only \
  --tmpfs /tmp:rw,noexec,nosuid,size=64m \
  --cap-drop ALL \
  --security-opt no-new-privileges:true \
  -p 127.0.0.1:8000:8000 \
  challenge:local
```

Проверка без расхода квоты OpenCode Go:

```sh
docker ps --filter name=challenge
curl --fail http://127.0.0.1:8000/api/health
```

Ожидается `{"status":"ok"}`. При ошибке посмотрите `docker logs --tail 50 challenge`.
Повторно запускать `docker run` с тем же именем нельзя; сначала нужно отдельно
остановить и пересоздать существующий контейнер. После изменения `.env` контейнер
тоже нужно пересоздать: обычный `docker restart` не перечитывает `--env-file`.

## 5. Доступ через SSH

В новом терминале **на Mac**, не на VPS:

```sh
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18000:127.0.0.1:8000 root@IP_СЕРВЕРА
```

Оставьте терминал открытым и перейдите в браузере на <http://localhost:18000>.
Используем порт 18000 на Mac, чтобы не конфликтовать с локальным бэкендом на 8000.
Для нестандартного SSH-порта добавьте `-p ПОРТ`.

Соединение до VPS зашифровано SSH. Порт приложения привязан только к loopback
сервера: **не заменяйте** `127.0.0.1:8000:8000` на `8000:8000` и не открывайте
порт 8000 в файрволе. Nginx и домен для такого режима не требуются.
Это доступ только для владельца SSH-учётной записи, не публичный сайт.

На общем сервере loopback доступен и другим локальным процессам. Для публичного
сайта нужны отдельные авторизация, HTTPS и защита квоты. Ни API-ключ в окружении,
ни Docker сами по себе не ограничивают доступ посетителей к API.
